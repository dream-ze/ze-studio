## 要解决什么问题

实时数据链路里，“任务没有推送数据”是很常见的问题。原因可能出在任何一环：上游没有数据、处理逻辑把数据过滤掉了、调度没有触发、下游写入失败。排查时要在几个系统之间来回查日志和数据，很花时间，而且步骤高度重复。

## 想法

把排查步骤整理成 agent 可以执行的流程：给它一个“没有推送”的任务，它沿着链路一环一环检查，每一步都给出证据，最后说明问题最可能出在哪里。

## 为什么值得做

- 这是数据工程里真实存在的痛点。
- 它正好是数据工程和 Agent 的结合点。
- 排查结论必须有证据，这对 agent 的可解释性是一个很好的练习。

## 下一步怎么验证

做一个脱敏的通用 demo：用模拟的 Kafka、Flink、Elasticsearch 数据搭一条小链路，人为制造几种“不推送”的情况，看 agent 能不能定位出来。先跑通最小的一种情况。
